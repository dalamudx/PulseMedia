# Configuration browser regression

Opt-in integration test for a **disposable local PostgreSQL 18 / App.Run fixture**. Do not use a user database, user Chrome profile, `.env`, credentials or downloads. The test creates and edits synthetic endpoints/subscriptions, signs into a fixture-only account and runs a local HTTP feed. It never downloads torrents.

## Prerequisites

Use the repository's `.mise.toml` tools and locked web dependencies. Chrome must expose CDP on `127.0.0.1:9222` with its own temporary profile. Build the latest embedded SPA and Go executable (`mise exec -- task build`) before starting App.Run; testing a Vite build against an old binary is insufficient.

1. Create a unique disposable PG database; run all `migrations/` with goose.
2. Seed `web/tests/configuration-fixture.sql` **only into that database**. Roots intentionally have no completed baseline, so automatic download acquisition stays gated.
3. Start `cmd/pulsemedia` with that database, a unique temporary data directory, an explicit fixture setup token and a test-only master key. Keep the key stable over fixture restarts, never print it. Listen on `127.0.0.1:8187`.
4. Start Chrome with `--headless=new --no-sandbox --disable-dev-shm-usage --remote-debugging-port=9222 --user-data-dir=<unique-temporary-profile>` (omit `--no-sandbox` when supported). Own both processes and stop/wait them after the check. Give them finite deadlines.
5. Run:

```sh
mise exec -- env PULSE_UI_FIXTURE=1 \
  PULSE_UI_BASE_URL=http://127.0.0.1:8187 \
  PULSE_UI_CDP_URL=http://127.0.0.1:9222 \
  PULSE_UI_SETUP_TOKEN=<the-fixture-token> \
  PULSE_UI_DATABASE_URL=<the-disposable-local-dsn> \
  pnpm --dir web test:configuration-ui
```

The script owns/closes its browser context and HTTP fixture even on failure. Stop App.Run/Chrome, wait for exit, then drop the uniquely named database and remove only the temporary directories you created. Existing initialized fixture runs must use the documented fixture account in the script; never reset other accounts.

## Coverage and limits

Versioned subscription control lost committed receipt / same-key retry / conflict reload / confirmed write followed by read failure; explicit candidate accept/hold reasons and pure-cache read with 503 removing old accept; policy draft preview/create/publication, lost committed receipt with locked draft and same key retry, version conflict/reload, frozen history restore into a higher revision, confirmed publish followed by read failure, non-default policy subscription selection and paused policy switch; actual App.Run scheduled health failure/backoff/recovery and failed state read removing old online observations; RSS version conflicts/reload, exact HTTP feed receipt/poll/disable, blank credential metadata edit, explicit creation bindings/target-root reference selection, foreign-root unresolved global acquisition protection (never green), own-only requirement withdrawal after a dropped committed HTTP receipt with same-key replay and retained unknown physical protection, lost committed PUT receipt and stable idempotent replay, confirmed PUT followed by failed refresh, paused state, TV season/unit preservation, poster rendering, refresh, keyboard focus, 390px overflow and empty/error discovery are behavioral assertions. All user command writes, bindings/types/unit keys/versions and configuration/status reads use real HTTP/PG. The imported-to-read-failure visual check explicitly seeds and restores a PG fact in an unbound synthetic movie; it temporarily resumes that unbound, recorded-owned fixture so the actual App.Run projector must write a complete current stamp, then verifies root-offline commit immediately masks cached green and a real UI refresh removes it, finally pauses it again; it does not run a real scanner or establish physical NAS file existence. Candidate explanations use an explicitly seeded synthetic completed round/candidate relation; they do not authorize downloads. A separate explicit PG synthetic unknown task/lane plus two requirement actors validates global protection and own-only withdrawal; no Add/Remove request is sent. The baseline, root protection and imported facts are fixture data, not proof of external state. The database URL is only accepted for local, passwordless `pulse_*` disposable databases and is not passed to psql as a DSN or printed. Discovery and metadata/poster reads are explicitly controlled transport fixtures, **not live TMDB validation**; list enrichment changes only optional poster metadata. Screenshots are written to `/tmp/pulse-config-ui-{desktop,mobile}.png` and `/tmp/pulse-policy-{desktop,mobile}.png` for inspection. Policy mobile capture waits for the drawer transform to settle before inspecting controls; a mid-transition capture is not responsive evidence.

Passing this test does not certify real downloader/NAS/media-server integration, complete health/protocol configuration, automatic TV/upgrade or the M2 stage as a whole.
